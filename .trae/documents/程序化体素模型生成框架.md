# 程序化体素模型生成框架（PCG） · 实施计划

## Context（为什么做）

现有 [VoxelGenerator.gd](file:///d:/Work/GodotProject/GodotVoxelSupport/addons/VoxelSupport/Runtime/VoxelGenerator.gd) 是**世界/地形粒度**的生成器（入参 `chunk_key` → 32³ 缓冲），项目缺少"造一个有界模型（树/岩石/建筑/道具）"的能力。

关键发现：现有框架**早就预留了有界模型这条路**——`VoxelGenerator.set_grid_size` / `set_chunk_bounds` 的注释明确写着"**有限模板生成器，如建筑蓝图**"，且 [VoxelData.gd](file:///d:/Work/GodotProject/GodotVoxelSupport/addons/VoxelSupport/Runtime/VoxelData.gd) 的 `grid_size` + `generator` 组合本就支持有界世界，`VoxelData` 还会自动补一个 `VoxelMemoryStream` 作为编辑落脚点。

因此**不新建任何渲染/节点类**：

- **每个模型 = 一个有界 `VoxelData`（`grid_size` 限定 + `generator` 挂 PCG 生成器）+ 一个现有 `VoxelRenderer` 节点**，直接复用整条渲染 / 碰撞 / LOD / 编辑链路。
- 唯一新增的是 **PCG 侧的生成器与 SDF 算子**，产出"按有界区域确定性生成的体素"。
- 现有生成器体系**全面重命名进 PCG 命名空间**（当前无外部实际依赖，改动面小、可控）。

## 决策汇总

| 议题 | 决定 |
|---|---|
| 模型承载 | 一模型一 `VoxelData`（有界）+ 一 `VoxelRenderer`，不新增节点类 |
| 命名 | 目录 `PCG/`，类前缀 `Pcg*`；SDF 为 PCG 下的子模块 |
| 重构范围 | `VoxelGenerator` 等生成器体系全面重命名到 PCG 命名空间 |
| 复用优先 | 尽量复用现有逻辑；尽量使用 Godot 内置能力 |

### 命名修订（第 2 版）

实施后复核发现：`PCG/` 里混了三层不同语义，`Pcg` 前缀把"框架契约 + 建模原语"都误标成了"程序化生成"。最终调整为：

| 层 | 类 | 位置 | 说明 |
|---|---|---|---|
| 生成器契约 | `VoxelGenerator`（@abstract） | `Runtime/VoxelGenerator.gd` | 服务所有数据源，非 PCG 专属（原 `PcgGenerator` 回归框架 `Voxel*` 命名） |
| 形状建模原语 | `Sdf` / `SdfSphere` / `SdfBox` / `SdfCylinder` / `SdfCapsule` / `SdfUnion` / `SdfSmoothUnion` / `SdfSubtract` / `SdfIntersect` / `SdfTransform` | `SDF/` | 建模能力（去 `Pcg` 前缀），与 `Runtime/`、`PCG/` 平级 |
| 程序化生成 | `PcgSdfGenerator`（extends `VoxelGenerator`） | `PCG/PcgSdfGenerator.gd` | 唯一真正的程序化生成步骤（SDF → 体素） |

下方 Part A / Part B 保留为修订前记录。

## Part B：SDF 子模块 `PCG/SDF/`

2. **`PCG/SDF/PcgSdf.gd`**（`@abstract Resource`，`@tool`，可在 inspector 里组合成树）
   - `@abstract func sample(p: Vector3) -> Vector2`（x = 距离，`<0` 实心；y = 材质ID）
   - `func bounds() -> AABB`（体素域参考，供上层推导尺寸）
   - 原语：`PcgSdfSphere` / `PcgSdfBox` / `PcgSdfCylinder` / `PcgSdfCapsule`（各带 `@export` 参数 + `material_id`）
   - 组合（各持 `a/b: PcgSdf`）：`PcgSdfUnion` / `PcgSdfSmoothUnion`（`@export k`）/ `PcgSdfSubtract` / `PcgSdfIntersect`
   - 变换：`PcgSdfTransform`（`translate` / `rotate` / `scale`）
   - 材质传递：组合算子取"更近者"的材质ID。

3. **`PCG/PcgSdfGenerator.gd`**（`extends PcgGenerator`，`@tool`）—— PCG 与现有框架的接合点
   - `@export var field: PcgSdf`
   - `_generate_chunk(chunk_key) -> PackedInt32Array`：`base = chunk_key * VoxelChunk.CHUNK_SIZE`，逐体素中心采样 `field.sample()`，`d <= 0` 写入 `material_id`
   - `_generate_chunk_lod(block_key, lod)`：粗粒度采样（每格取中心，`2^lod` 步长）
   - 有界范围直接由 `VoxelData.grid_size` → `set_grid_size` 驱动，**无需额外裁剪逻辑**
   - 确定性：纯函数，不引入随机；如后续需要随机细节，用 `seed` 派生 `RandomNumberGenerator` 传入

> 不需要单独的"光栅化器/模型容器"：`PcgGenerator` 的按 chunk 出缓冲接口本身就是光栅化入口，产出直接进 `VoxelData`，最大程度复用框架。

## Part C：一模型一 VoxelData + VoxelRenderer 的落地方式

4. 使用方式（无需新代码）：
   - 建一个有界 `VoxelData`：`grid_size = Vector3i(x, y, z)`，`generator = PcgSdfGenerator`（内嵌 SDF 组合树）
   - 建一个 `VoxelRenderer` 节点，`data` 指向该 `VoxelData`
   - 需要碰撞时打开 `VoxelRenderer.generate_collision`（现有开关）

5. **每个模型必须各自的 `VoxelData` 实例**（`VoxelData` 是 `Resource`，多渲染器共享同一实例会互相干扰）。
   - 推荐做法：**把"一个模型"做成一个场景**（`VoxelData` 设为 **local to scene** 内嵌资源 + `VoxelRenderer` 作为子节点）。实例化该场景即得到互不影响、可各自挂脚本的模型节点。

6. 新增 demo：`demo/pcg_models_demo.gd` + 场景，放两个独立模型（不同 SDF 组合 / 不同 seed），验证互不影响。

## Godot 内置能力优先

- 噪声：`FastNoiseLite`（内置，现有 demo 已在用）
- 随机：`RandomNumberGenerator`（内置，由 `seed` 派生）
- 资源/检视器：`Resource` + `@export` + `@tool`（SDF 树在 inspector 里可视化组合）
- 数学：`Vector3` / `Basis` / `Quaternion`（SDF 变换直接复用）
- 烘焙：`ResourceSaver`（内置）
- 碰撞：直接复用 `VoxelRenderer` 现有 `generate_collision`（不重写）

## 复用清单（不重造）

- 渲染 / 碰撞 / LOD / 编辑：整条 `VoxelData` + `VoxelRenderer` 链路
- 异步编排：`VoxelAsyncLoader`（零改动，只是类型名更换）
- 常量：`VoxelChunk.CHUNK_SIZE` 等
- 材质：`VoxelMaterial`

## 验证

1. `mcp_devframework_validate` 校验全部新增/改动脚本无解析错误。
2. 运行 `demo/pcg_models_demo.gd` 场景：两个模型各自渲染，材质/透明面正常，互不影响。
3. **回归**：运行 `demo/streaming_demo.gd` 地形场景，确认重命名后世界地形仍正常（这是重命名的主要风险点）。
4. 打开某模型的 `VoxelRenderer.generate_collision`，让物理体掉落验证碰撞。
5. 改 `grid_size` / SDF 参数后重建，确认有界范围与形状随之变化。

## 本期不做（范围外）

- 不改几何/渲染内核命名（`VoxelChunkGenerator` / `VoxelMeshGenerator` / `VoxelRenderer`…）。
- 不做 L-system / CA / WFC 算子（`PcgSdf` 抽象已为后续技术预留同级扩展位）。
- 不做 marching cubes 平滑网格（SDF 已就绪，后续可接）。
- 不做 `.qvox` 写出（读取已支持；写出需构造 `QVoxDocument`，成本较高，后续可选）。

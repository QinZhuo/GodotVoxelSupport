# QVX 格式规范 — v4

> **定位**：`.qvx` 是一个**体素模型容器**，与 MagicaVoxel 的 `.vox` 同级——
> 可独立分发、可直接观察、可作为项目资产被编辑器导入的**源文件**，
> 不是烘焙中间产物或临时文件。同一个容器**也**能承载"整个世界存档"
> （多模型 + 增量写盘），但那是它的用法之一，不是它的身份。
>
> 配套实现（`addons/VoxelSupport/`）：
> - **格式内核** `QVoxelSpec` / `QVoxelBlockCodec` / `QVoxelFile`（定义、编解码、读写与校验）
> - **资产导入** `QVoxelAsset.from_file()`：`.qvx` 的块级视图（材质 + 每个 `VXEL` 的块 + `NODE` 摆放）。
>   `.vox` 由 `VoxAsset` 承载 —— 两种源格式的概念形状不同（详见 QVoxelAsset 类注释），
>   导入器按扩展名分派，不共用适配器
> - **世界存档** `QVoxelStream`：可写、脏标记、增量落盘
>
> 编辑器导入器（`addons/VoxelSupport/Importer/`）**同时识别 `.vox` 与 `.qvx`**，
> 在导入面板可选四种产物：
> - `Voxel Data Resource` → `QVoxelSource` (.res)：运行时体素数据（可破坏 / 动态修改）
> - `Voxel Mesh` → `ArrayMesh` (.mesh)：静态网格
> - `Voxel MeshLibrary` → `MeshLibrary` (.res)：网格库（by model / node / frame）
> - `Voxel No Import` → 空 `Resource`：只要原始文件、不做导入
>
> `demo/samples/*.qvx` 是可直接 hexdump 对照的样例，同时是
> `Scripts/Test/test_qvox_format.gd` 的测试夹具（随 `.gitattributes` 走 Git LFS）。

> **单一文件。单一数据流。每条事实只存一次。**

---

## 0. 设计原则

五条规则，其余一切由此推导。

| # | 原则 | 学自 | 推论 |
|---|---|---|---|
| **P1** | **整个文件就是一条带类型的块流，别无其他** | PNG / GLB | 文件即块。新功能 = 新块类型。旧读者遇到就跳过。 |
| **P2** | **每条事实只存一次** | ——（第一性原理） | 任何字段不得可由其他字段推导。不存可数出来的计数。 |
| **P3** | **元数据用 JSON，负载用列式二进制** | GLB / SPZ | 人读头部，机器读打包的列；压缩率提升 3–5×。 |
| **P4** | **块头自足：读到块头即知全部** | FlatBuffers | 长度、类型、校验值都在 payload 之前。 |
| **P5** | **缓存是派生的，且可证明可删除** | SPZ / FlatBuffers | 能重算的块就标明"可重算"，与其来源校验，且删之无害。 |

## 1. 块类型

文件 = 8 字节签名 + 一个或多个块（第一个必须是 `HEAD`），在最后一个块结束时结束，
没有终止符。当前共七种类型；这个集合应当缓慢增长，且每次增加都需要理由。

| 类型 | 数量 | 必需 | 可删 | 用途 |
|---|---|---|---|---|
| `HEAD` | 恰好 1 个 | ✅ 必须第一 | ❌ | 声明文件。JSON。 |
| `MATE` | ≤ 1 | 否 | ❌ | 材质调色板。 |
| `VXEL` | ≥ 0 | 否* | ❌ | 体素数据（静态）。每个模型一个。 |
| `ANIM` | ≥ 0 | 否* | ❌ | 帧动画数据 + 时序。每个动画一个。 |
| `NODE` | ≤ 1 | 否 | ❌ | 场景树（只放 `nodes`）。JSON。 |
| `CAMR` | ≤ 1 | 否 | ❌ | 相机书签。JSON。 |
| `CACH` | 任意 | 否 | ✅ | 任何可重算的数据。 |

\* 没有 `VXEL` / `ANIM` 的文件是合法的——例如一个纯资产数据库。渲染器需要关心的
体素场景至少有一个。**两者按 `model_id` 互斥**：一个 `model_id` 要么是静态 `VXEL`、
要么是 `ANIM` 动画，不能同时是。

> **v4 的三处收敛**：① `HEAD` 的 `channels` 数组（恒为长度 1、却暗示多通道）改为扁平单键
> `"channel":"material"` + `"bpp":16`；② `NODE` 一肩挑三事拆成 `NODE`/`CAMR`/`ANIM`；
> ③ 动画时序（fps/loop/tags）从 `NODE` 节点条目收进 `ANIM` 块，与体素帧内聚一处。

删除全部 `CACH` 块后，文件必须加载出**完全相同的结果**——只是首次加载更慢（P5）。

## 2. 节点摆放（NODE 的 `nodes[]` 条目）

场景树是**嵌套**的：每个节点是一个 JSON 对象，`kind` 取 `group`（容器，带 `children`）或
`model`（叶子，带 `model_id`）。节点的摆放只有一处真值 —— 一个 `transform` 键：

```json
{ "kind": "model", "model_id": 0, "name": "body",
  "transform": { "t": [1, 2, 3], "r": [x, y, z, w], "s": [1, 1, 1] } }
```

- `t` 平移（体素单位，整数）、`r` 旋转（单位四元数，与 glTF 同构）、`s` 缩放（三者皆可缺省）。
- 缺省 = 恒等，**不写字面量**（P2）：`transform` 键整体缺失即恒等。
- 轴对齐 90° 旋转（`.vox` 的 24 朝向的等价物）是**整数保序**的，体素盒不被破坏；
  非轴对齐旋转 / 缩放由运行时导入器逐体素融合处理，编辑器世界按"不旋转 + 告警"处理。
- 读写唯一实现：`QVoxelTransform.transform_from_json` / `transform_to_json`。**全项目不得另抄一份**。

节点摆放是**静态属性**：一个节点只有 `transform` 一份摆放，不随时间轴变化。
动画只存在于 `ANIM` 块里，按 `model_id` 描述该模型自己的体素帧。

> **为什么不做节点/组摆放动画**：当前编辑器专注 Aseprite 式的**体素逐帧动画**。
> 节点/组变换动画会让"模型内容帧"和"物件摆放轨"两套时间语义并排存在，增加格式、
> 播放与 UI 的复杂度。导入 `.vox` 时，nTRN 多帧摆放与 nSHP 逐帧换模型都会**烘焙成
> 体素帧**（按全局帧把世界变换与模型内容写进 `ANIM`），再作为普通体素动画编辑。
>
> **`anim.tags` 就是 Aseprite 的 tag**：每项 `{name, from, to, direction, color, repeat}`；
> `direction ∈ {forward, reverse, pingpong, pingpong_reverse}`，`repeat=0` 表示无限循环。
> 它只是命名帧区间，不拥有独立轨道，也不叫 Clip。

## 3. `.vox` ⇄ `.qvx` 的图层 / 组映射

`.vox` 的 `LAYR`（图层，含 `_name` / `_hidden`）与 `.qvx` 的组**一一对应**：
一个图层 = 一个 `QVoxelGroup`，**组名 = 图层名**，**可见性 = `_hidden` 的反**。导入器
（`VoxAssetWorld.to_world()`）从 `node 0` 递归、跳过隐藏图层的整棵子树、同一模型被多个形状引用
就摆多份 —— 于是世界第 k 帧的体素集合与 `.vox` 的 `VoxAsset.get_voxels(k)` **逐格一致**
（动画已在导入时烘焙成体素帧，见 §4.3）。`.qvx` 与 `.vox` 因此都落到同一个 `QVoxelWorld`，
渲染只有一套语义。

## 4. 动画模型（核心设计）

### 4.1 定位：体素版 Aseprite

编辑器只做**体素逐帧动画**，不做通用三维动画系统：

- 一帧 = 一整套体素块表
- 动画 = 帧序列 + 逐帧时长 + 标签
- 编辑、求值、渲染、拾取都只读**当前帧**
- **帧就是动画的唯一真值**

因此不引入以下概念作为编辑器的一等公民：

- 节点/组摆放动画轨
- 骨骼、蒙皮、骨骼动画
- 关键帧插值、动画曲线
- 多轨/混合/独立 Clip

这不是能力缺失，而是产品边界：目标是让用户像用 Aseprite 编辑像素帧一样编辑体素帧。

### 4.2 数据形态

- `ANIM`：按 `model_id` 绑定，包含体素帧、逐帧时长、fps、loop、tags
- `NODE`：只保留静态 `transform`，不随时间轴变化
- 一个 `model_id` 恰好一个体素源：`VXEL` XOR `ANIM`
- 编辑器内存中每帧保存完整块表；`.qvx` 落盘时 `ANIM` 使用块级增量控制文件体积

### 4.3 `.vox` 导入：所有动画烘焙成体素帧

`.vox` 的以下动画在导入时统一转换为体素帧：

- `nTRN` 多帧摆放
- `nSHP` 逐帧换模型
- 两者混合

导入算法：

1. 全局帧数 = 所有节点关键帧的最大帧号 + 1
2. 逐帧预计算每个节点的世界变换；缺失帧沿用上一关键帧
3. 对每个模型实例，把第 k 帧相对第 0 帧的变换差烘焙进局部体素坐标
4. 所有帧的并集包围盒作为该模型的分辨率
5. 保留原有节点/组层级；组本身保持第 0 帧静态摆放，组的运动烘焙进子树模型
6. 只有真正发生变换/换模型的实例才生成动画帧；静态实例保持静态
7. 结果就是普通的 `QVoxelModel.frames`，可逐帧编辑、打标签、保存为 `ANIM`

约束与误差：

- `.vox` nTRN 是轴对齐 90° 变换，烘焙后体素坐标仍为整数
- 非轴对齐旋转/缩放会离散化到网格，可能有取整误差
- `.vox` 不含逐帧时长，导入使用模型默认 fps（4），用户可在时间轴调整

### 4.4 标签：Aseprite Tag，不是 Clip

`anim.tags` 每项：

```json
{
  "name": "idle",
  "from": 0,
  "to": 3,
  "direction": "pingpong_reverse",
  "color": "#3399e6",
  "repeat": 2
}
```

- `direction ∈ {forward, reverse, pingpong, pingpong_reverse}`
- `repeat = 0` 表示无限循环
- 标签只是**命名帧区间**，不拥有独立轨道、独立时长或事件
- 因此它叫 Tag，不叫 Clip；真正的 Clip 需要独立多轨/事件，当前不做

时间轴交互：

- 顶部标签条直接拖左/右边缘改范围
- 拖标签中间整体平移
- 单击标签预览该区间
- 下拉选择标签直接预览
- 右键预览 / 编辑 / 改颜色 / 删除
- 一次拖拽或一次弹窗确认 = 一条撤销记录

### 4.5 取舍与边界

优点：

- 数据模型只有一种动画形态，UI 与撤销逻辑简单
- 导入动画立刻可逐帧编辑
- 播放器、时间轴、标签、导出只需要理解体素帧
- 符合像素编辑器的用户心智

代价：

- 整体运动会被烘焙成每帧重复体素，内存随帧数增长
- 导入后不能非破坏性地调整物件运动曲线
- 动画实例之间共享变弱
- 缩放/非轴对齐旋转需要离散化

后续可优化方向：

- 记录原始 `.vox` 路径 / 导入设置，支持重新烘焙
- 未变化帧共享、实例共享
- 大动画的帧数/分辨率预估提示
- 运行时需要的物件动画放在运行时层或导出层，不反向污染编辑器格式

明确不做：

- 不恢复 `transform_tracks` / `transform_keys`
- 不恢复骨骼/蒙皮
- 不把标签改名为 Clip
- 不把节点变换动画塞进 `ANIM`

## 5. 程序化生成（AI / 脚本）

`.qvx` **不在文件里塞"文本形态"** —— 需要"用代码生成模型"时，直接写一段 GDScript 拼体素、再
`QVoxelFile.serialize(doc)` 落盘即可（范例：`demo/warrior_voxel.gd`）。AI 写代码（循环 / 函数 /
复用 / 参数化）比手写二进制或文本块都更强、更可靠，故格式本身保持纯二进制、单一解析路径。

# QVX 格式规范 — v4

`.qvx` 是体素模型容器，也是 QVoxelier 的工程源文件。可承载单个模型或整个世界存档。

- 单一文件、单一数据流
- 每条事实只存一次
- 元数据用 JSON，体素负载用二进制
- 格式内核：`QVoxelSpec` / `QVoxelBlockCodec` / `QVoxelFile`
- 世界与编辑模型：`QVoxelWorld`
- `.vox` / `.qvx` 都通过导入器落到同一个 `QVoxelWorld`

## 1. 设计原则

| 原则 | 含义 |
|---|---|
| P1 | 文件就是一条带类型的块流 |
| P2 | 每条事实只存一次，不存可推导值 |
| P3 | 元数据用 JSON，负载用二进制 |
| P4 | 块头自足：长度、类型、校验值都在负载前 |
| P5 | 缓存可重算、可删除 |

## 2. 块类型

| 类型 | 数量 | 用途 |
|---|---|---|
| `HEAD` | 1 | 文件声明，必须第一 |
| `MATE` | ≤1 | 材质调色板 |
| `VXEL` | ≥0 | 静态体素，每个模型一个 |
| `ANIM` | ≥0 | 体素帧动画 + 时序 |
| `NODE` | ≤1 | 场景树 |
| `CAMR` | ≤1 | 相机书签 |
| `CACH` | 任意 | 可重算缓存 |

一个 `model_id` 只能有一个体素源：`VXEL` XOR `ANIM`。

v4 收敛点：

- `HEAD` 使用单通道 `channel` + `bpp`
- `NODE` / `CAMR` / `ANIM` 分块
- 动画时序收进 `ANIM`

## 3. 节点摆放

`NODE` 是嵌套场景树：

- `group`：容器，带 `children`
- `model`：叶子，带 `model_id`

节点摆放只有静态 `transform`：

```json
{ "t": [1, 2, 3], "r": [x, y, z, w], "s": [1, 1, 1] }
```

- 缺省 = 恒等，不写空值
- 轴对齐 90° 旋转保持体素整数
- 节点摆放不随时间轴变化

`.vox` 图层映射为组：组名 = 图层名，可见性 = `_hidden` 的反。

## 4. 动画模型

编辑器只做体素逐帧动画，定位类似 Aseprite：

- **一帧 = 一整套体素块表**
- 动画 = 帧序列 + 逐帧时长 + 标签
- 帧就是动画的唯一真值

`.vox` 的 `nTRN` 多帧摆放、`nSHP` 逐帧换模型，以及两者混合，导入时统一**烘焙成体素帧**：

- 保留节点/组层级，组变换保持静态
- 物件运动烘焙进子树模型的逐帧体素
- 只有真正变化的实例才生成动画帧
- `.vox` 无逐帧时长，导入使用默认 fps

标签是 Aseprite 风格的命名区间，不是 Clip：

```json
{
  "name": "idle",
  "from": 0,
  "to": 3,
  "direction": "pingpong_reverse",
  "color": "#3399e6",
  "repeat": 2
}
```

- `direction`：`forward` / `reverse` / `pingpong` / `pingpong_reverse`
- `repeat = 0` 表示无限
- 标签不拥有独立轨道、独立时长或事件

明确不做：

- 节点/组摆放动画轨
- 骨骼、蒙皮
- 动画曲线 / 关键帧插值
- 多轨 Clip

代价与方向：

- 物件运动会烘焙成每帧重复体素，内存随帧数增长
- 导入后不能非破坏性调整运动曲线
- 后续可做：重新烘焙元数据、未变化帧/实例共享
- 运行时物件动画放在运行时或导出层，不污染编辑器格式

## 5. 程序化生成

`.qvx` 不存文本形态。需要程序化生成时，直接写 GDScript 拼体素，再用
`QVoxelFile.serialize(doc)` 落盘。AI 写代码比生成文本块更可靠，格式保持单一解析路径。

分层方向：`Core → Format → Model → Mesh → Data → Runtime → Tools`（Importer 与 Tools 同级）。

### 2.2 为什么原来的分层不成立

改之前 `Dynamic/` 一个目录占全部代码 **58%**，里面同时住着数据层、渲染器、两个视点层、
破坏系统、粒子、脏账本、LOD 数学。更根本的问题是 `Mesh/` 语义混乱：
`VoxelChunk` / `VoxelVolume` / `VoxelWorldUtil` 是**最底层叶子**（谁都不依赖），
而 `QVoxelScript` / `QVoxelBuilder` / `QVoxelMeshExport` / `QVoxelPreview` 是**依赖 Model 的上层工具**。
它们放在同一个目录里，导致「分层」只是命名上的 —— `Mesh/` 对 `Model/` 有 17 条反向边。

### 2.3 验证方式（不靠纪律，靠静态分析）

去注释后按类名整词统计每个目录对其他目录的提及数：

```
             Core   Format    Model     Mesh     Data  Runtime    Tools Importer
  Core          64        0        0        0        0        0        0        0
  Format       171       97        0        0        0        0        0        0
  Model         86       65      144        0        0        0        0        0
  Mesh          70       14        0       15        0        0        0        0
  Data         183       15        4        7       63        0        0        0
  Runtime      101        2        0       18       23       70        0        0
  Tools         22        4       41        3        0        0       31        0
  Importer      25       10        0        4        4        0        0        8
```

**主对角线上方全为 0 —— 严格单向，无向上依赖边。**

> 移动文件时的坑：`move_file` **只搬 .gd，不搬 .gd.uid**；引擎随后为新路径生成**新 uid**，
> 旧 .gd.uid 成为孤儿。正确顺序是**先搬 .uid 再搬 .gd**，这样 uid 值完整保留（场景引用不失效）。
> 本轮 49 次移动全部按此顺序，比对 51 个 uid **changed 0**。

## 3. 两个视点层合并成一个

| | 改前 | 改后 |
|---|---|---|
| 类 | `VoxelInfiniteLayer`(1288, RefCounted) + `VoxelPagedLayer`(1366, Node3D) | `VoxelViewLayer`(1315, Node3D) |
| 行数 | 2654 | 1315（**−1339**） |
| 同名函数 | 44 个 | — |
| 逐字重复 | 500~800 行 | 0 |

**为什么「三层并存」是最糟的状态**：渲染器用 `infinite_layer` 惰性 getter（必然实例化、永远被调），
同时又留了 `paged_layer` 可空引用 + `uses_paged_layer()`，四个薄壳
（`_filter_visible` / `_view_unload_d` / `_view_lod_outer` / `_flush_lod_mesh_apply_queue`）
在两条路径间分叉，而 `remove_chunk_mesh` 之类的地方**无条件同时调两边的回调**。
谁也删不掉谁，且已经分叉出 3 处行为差异。

新层的关键设计：

- **不惰性 new**：`view_layer` 是可空引用。`view_layer == null` 是一条**真实可走的最简路径**
  （无剔除 / 无流式 / 无 LOD），不是降级兜底。
- **旋钮搬家**：`_stream_load_per_frame` / `_stream_unload_per_frame` / `_lod_build_per_frame` /
  `_lod_preload_blocks` / `_lod_submit_per_frame` 共 6 个私有 @export 从渲染器搬进视点层。
  全仓 .tscn **0 引用**这些键，故不破坏任何装配；`view_distance` / `unload_distance` / `lod_count`
  被 3+2+3 处场景写，**留在渲染器**、由视点层单向读取。
- **4 张平行表合成 1 张**：旧层维护 `_lod_pending_tasks` / `_lod_rebuild` / `_lod_null_retry` 等
  4 个同 key 空间字典，新层是 `_levels[level][block_key] = {gen, pending, rebuild, retry}`。
- **只用宿主公开面**：新层不碰渲染器任何下划线成员（改前旧层反向读宿主 7 个私有 @export）。
- **写指针压缩**取代 `remove_at` 逐个删除（挂载队列）。

同时修掉的 P0：`remove_chunk_mesh` **漏了 `_chunk_arrays.erase`** —— 分组绘制模式下 chunk 被卸载后，
下一次整组重建会把这个已卸载 chunk 的缓存几何无条件拼回去（**幽灵几何复活**），
且 CPU 侧数组单调增长。`_rebuild_group_meshes` 还缺 `data` 空判（data 置空 + `_group_dirty` 非空会抛 null）。

### 4.2 三个行为变化（有意为之）

1. `VoxelMaterial.air_mate()` 现在返回 **12 键**（含 r/g/b/a），不再是 8 键。
   旧的 8 键条目在 `material_color()` 里会落到「缺键则缺省 r=255,g=0,b=255」，即**洋红**。
2. `QVoxelWorld.material_color()` 对历史 8 键条目不再返回洋红（只认 `rgba`）。
3. `QVoxelWorld` 新增 `dropped_nodes` 字段：NODE 树里被丢弃的子树现在有可读诊断
   （改前 `QVoxelFile` 算出来的 dropped 诊断对 `QVoxelWorld` 完全无效，静默丢子树 / 静默覆盖）。

### 4.3 性能修掉的 6 项

| # | 问题 | 修法 |
|---|---|---|
| 1 | `get_voxel_count()` 每帧 O(已加载 chunk) 求和（HUD 在调） | 增量镜像字段 `_voxel_count_total`，O(1) |

| 3 | `_snapshot_chunks_halo` 对每个待建 chunk 同步 preload 27 邻居（主线程磁盘 IO，邻域高度重叠） | 先去重再预载，只为「真的缺」的块付读盘 |

| 5 | 粒子纹理 3N 次 `set_pixel` + 每点新建 Color | PackedByteArray + 一次 `Image.create_from_data(FORMAT_RGBAF)`；材质表每次导出只建一次 |
| 6 | `VoxelDestructible` 里「分组-取材质-移除-掉落体」流水线手写 5 份 | 收敛成 `_consume_voxels(positions, opts)`，行为逐处等价（应力 mat_default=0 / 崩塌=-1 等差异用 opts 表达） |

## 7. VoxelMorphMap：从零引用变成真能力

改前它是 **217 行、全仓 0 引用**（只有 README 提到它）。本轮接成 `VoxelParticleView` 的
`@export var spatial_sort`：按 Morton 码重排点云，让相邻空间位置在点数组里相邻，
提升 GPU 缓存命中（粒子只做位置采样，重排不改变点集本身，只改变顺序）。

新增两个 static：`sorted_indices(points, stride, mode)` 与 `reorder(points, order, stride)`。
配套把纹理烘焙抽成 `VoxelPointCloudExporter.textures_from_points(points)` ——
重排后**重烘焙**，而不是逐像素搬运三张纹理（后者是第二份 bpp/格式推断，容易与烘焙端漂移）。

## 8. 原生层修复（9 项）

| # | 问题 | 修法 |
|---|---|---|
| 1 | 构建产物名与 `.gdextension` 期望名不一致（`voxelsupport.dll` vs `libvoxelsupport.windows.release.x86_64.dll`），改名靠手 | CMakeLists 加注释说明改名流程；`.gitignore` 补新名的无后缀产物 |
| 2 | **库与源码零版本握手**：改了实现忘重建 = 静默加载旧 dll，`class_has_method` 校验全过 | `VOXEL_NATIVE_API_VERSION` + `build_id()`，`NativeLoader.EXPECTED_API_VERSION` 比对 |

| 4 | `qvox_pack_indexed` 把表长写 u8，表长 256 时计数写 0，整块静默消失 | 加 `table.size() > 255` 守卫返回空 |
| 5 | `voxelize_mesh` 在 slots 为空时 `tex[0]` 越界 | 预置默认 slot |
| 6 | crc32 表注释称「magic static 线程安全」，实现是手写 `built` 标志无同步 | `static const std::array` + lambda 初始化 |
| 7 | `generate_spheres_native` 在 **worker 线程**无条件 `print`（全文唯一 Godot 侧副作用） | 删除 |
| 8 | `greedy_merge_dense` 是 2D 旧方案残留（已 bind + 进 REQUIRED_METHODS + 全仓零调用） | 删除 |
| 9 | 注释里的「GDScript oracle」全部已不存在（`generate_arrays_from_chunks` / `QVoxelBlockCodec.unpack` 都是纯转发） | 清掉幻觉注释 |

> 版本握手的关键坑：Godot 4.7 的 `ClassDB.class_call_static()` 对 GDExtension 类报
> 「Cannot find static method.」并返回 0，用它握手会把**新库也判 0 永久拒载**。
> 必须先 `ClassDB.instantiate` 再 `inst.call("api_version")`。

> `generate_arrays_from_chunks` 已不存在，注释里指向它的「GDScript oracle」表述一并删除。

## 10. 刻意没做 / 留待下一步

| 项 | 为什么没做 |
|---|---|
| `QVoxelSource` 再拆 `VoxelLodStore`（~430 行粗层数据 + 降采样调度） | 拆分收益是「文件更短」，但粗层数据与 `_chunk_buffers` 共享快照生命周期（COW 守卫 / 计数账 / 不变式），搬出去会变成两个对象互相回调。**文件长不等于职责乱**，本轮优先收在「重复逻辑消失」上 |
| `QVoxelSource` 的 `_volume`（整块求值缓存）+ `_chunk_buffers`（分块编辑）双表示 | 两者服务不同访问模式（整块求值 vs 随机编辑），且 `_volume` 是惰性构建的回落路径。合并要先证明「求值永远可按块触发」 |
| 两套持久化入口（`save_data` 扁平数组 vs 隐藏属性块表 + gzip） | 「哪些块落盘」已收敛到 `VoxelPersistence.blocks_to_persist`，剩余差异是**载荷形状**（接口存档要完整扁平列表，资源持久化要压缩块表）。真正该统一的是「是否两套都需要」，属 API 决策 |
| `VoxelCollision` 对 STATIC 模式的整份碰撞体 | 这是新功能，不是重构 |
| `water_sim.gd` 的 `_update_water()` 遍历全部体素 | demo 层问题，与插件无关 |
| `Native/libvoxelsupport.*` 的 `~*.TMP` 残留 | 引擎加载动态库时的运行期副本，被进程锁定；`*.TMP` 已在 .gitignore |

## 11. 工具链踩坑（供下次参考）

1. **`move_file` 不搬 `.gd.uid`**：先搬 uid 再搬 gd，否则 uid 值变、场景引用可能失效。
2. **改完 `.gd` 必须重启编辑器才能跑测试**：否则 `run_tests` 报
   「检测到 N 个脚本的磁盘内容与已加载版本不一致，本轮拒绝执行（避免测旧代码）」。
3. **「A 有定义但 B 说找不到」先重启编辑器再判断** —— 编辑器脚本缓存陈旧会给出假 Parse Error。
4. **场景里可能早有陈旧路径**：`QVoxelier.tscn` / `editor_voxel_test.tscn` 等 4 个场景在本次改动前就写着
   `res://addons/VoxelSupport/Runtime/VoxelRenderer.gd`（该目录在 HEAD 里根本不存在），
   靠 uid 才加载成功。**uid 引用优于路径引用**，这是活证据。
5. **测试里的 `push_error` 会被 runner 记成失败**：验证「非法输入应被拒绝」的用例要断言返回值，
   不要真的让被拒绝路径 `push_error`。
